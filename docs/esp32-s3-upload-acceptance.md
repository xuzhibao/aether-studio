# ESP32-S3 上传与串口验收（实机）

本说明用于在装有 ESP32-S3 开发板的本机上验收 **构建 → 选端口 → 上传 → boot 日志 → 故障重试** 流程。所有步骤都以 Aether Studio 桌面版和真实 PlatformIO 为准；浏览器预览不执行命令。

> 验收边界：仓库中的自动化用例使用后端 fixture 和 Linux PTY 模拟失败、取消与重试；它们不能证明真实芯片已烧录或已启动。只有在本机连接真实开发板并完成下列物理步骤，才能记为实机 PASS。若本机没有明确属于本任务的开发板，不要尝试对随机 COM 口上传。

## 准备

1. 使用带数据线的 USB 连接 ESP32-S3 开发板；只供电的线无法枚举串口。
2. 确认 PlatformIO 可用：桌面版 **Plugins → PlatformIO** 显示可执行文件路径与版本。也可在终端运行 `platformio --version`。
3. 准备一个 ESP32-S3 工程（例如仓库的 `examples/platformio-esp32s3`），并保存到磁盘目录。
4. 关闭可能占用串口的其他工具（其他串口监视器、烧录工具、虚拟机串口转发）。

## 1. 构建

1. 打开磁盘工程目录，确认 `platformio.ini` 中的 `board` 与实际开发板一致。
2. 在 **Build Tasks** 点击 **Build with PlatformIO**。
3. 验收标准：任务状态为 `succeeded`、exit 0，日志包含 PlatformIO 的构建完成输出，并列出固件产物。失败时保留完整日志和退出码，不要以“有产物”替代任务状态。

构建成功只代表编译完成，不代表已烧录。

## 2. 选择端口

1. 点击顶部 **Deploy to Device**。
2. 在 **已枚举端口（操作系统报告）** 中找到刚连接的设备。列表会显示路径（如 `COM5`、`/dev/ttyACM0`、`/dev/cu.usbmodem…`）、厂商和 VID/PID。
3. 如果无法确认哪个是目标板：先拔下开发板，点 **刷新端口** 并记下列表；重新插上后再刷新，新增的端口就是本次 USB 连接对应的串口。不要仅凭端口名或厂商猜型号。
4. 点击该端口填入，或手动输入路径。留空时 **开始构建并烧录** 不可用。

厂商 `Silicon Labs`、`wch.cn` 等通常是 USB 转串口芯片的描述，不是开发板型号。

## 3. 上传

1. 若串口监视器正在连接，无需手动断开；点击 **开始构建并烧录** 后应用会先断开监视器，并确认端口已释放。若释放失败，任务不会启动，界面显示真实错误。
2. 上传开始后，任务卡片应显示 **正在上传…**，并可看到 PlatformIO 的实时日志和实际执行命令（包含 `--upload-port <端口>`）。
3. 成功验收标准：
   - 任务状态为 **上传命令成功（退出码 0）**，`exit 0`；
   - 日志包含 PlatformIO 上传完成信息（例如 `SUCCESS`）；
   - 开发板在烧录后复位或可手动复位。
4. 失败时状态为 **上传失败**，显示非零退出码和 PlatformIO/esptool 原始错误。不要根据旧任务或旧日志推断本次结果。

“退出码 0”只表示上传命令成功，不等于固件已运行或启动日志正常。

## 4. 查看 boot 日志

1. 在上传任务卡片点击 **连接串口监视器**（或打开 **Devices**，地址会预填最近使用的端口）。应用使用 `platformio.ini` 的 `monitor_speed`；示例工程为 `115200`。如果手动连接，确认波特率与固件一致。
2. 打开 **Serial Monitor**，按开发板的 **RST/EN** 键复位，或重新插拔 USB 后重新连接。
3. 预期看到芯片启动输出（ROM boot 信息、`rst:0x…`、`boot:0x…` 等，具体内容随芯片和固件不同）。若没有任何输出：确认端口和波特率、换数据线、检查固件是否启用串口输出；不要伪造 boot 日志。

## 5. 故障与恢复验收

逐项执行，并确认界面显示与日志一致：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 端口被占用 | 先用其他程序打开该串口，再上传 | 任务失败，显示非零退出码和端口占用/打开失败的真实错误；关闭占用程序后可重试 |
| 上传前监视器占用 | 先连接监视器，再上传 | 上传启动前监视器自动断开；若无法释放，任务被取消并显示错误 |
| 上传中拔线 | 任务运行中拔下 USB | 任务以失败结束，日志保留；监视器若在连接也会显示连接中断 |
| 取消上传 | 任务运行中点击 **取消上传** | 状态为 **上传已取消**，日志和命令保留；端口回到系统 |
| 失败后重试 | 修正端口/占用后点 **重试上传** | 启动新的任务 ID，不复用已结束任务；新任务重新构建并上传 |
| 拔线后重连 | 重新插上 USB，刷新端口后再连接 | 可建立新连接；旧句柄不会被复用；必要时重新选择端口 |
| 上传后连接 | 成功后点 **连接串口监视器** | 使用同一端口建立新连接，可查看日志，无需重新查找端口 |

## 6. 清理

1. 断开 Serial Monitor。
2. 关闭无关的串口工具，拔出开发板。
3. 不删除工程源码或用户数据；如需移除临时工程，用系统回收站。

## 与自动化验证的区别

| 验证 | 覆盖内容 | 不能证明 |
| --- | --- | --- |
| `npm run smoke` | 串口状态清理、关闭并发、读取失败后重连、默认波特率、首选端口 | 真实硬件、真实 PlatformIO 上传 |
| `npm run smoke:host` | PlatformIO 上传参数校验、非零退出、失败后重试为独立任务、取消 | 实际芯片烧录与 boot 日志 |
| `npm run smoke:ui` | Deploy 端口选择/手输、浏览器不伪造上传、真实错误展示 | 桌面原生串口枚举与上传 |
| `npm run smoke:desktop` | 桌面 OS PTY 串口、任务运行时禁止抢端口、真实 PlatformIO 上传非零失败与改端口重试 | 真实 ESP32-S3 芯片、烧录成功与 boot 日志 |
| 本说明 | 真实开发板、真实 USB 串口、真实 boot 日志 | 其他型号/固件的兼容性 |

只有在真实开发板上完成第 1–5 步，才可将实机验收记为 PASS；否则应记录为“未验证（无目标硬件）”。
